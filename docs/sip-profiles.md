# SIP Profiles

**Status:** IMPLEMENTED (model + persistence + GUI placeholders) — Task 6

## Overview

A SIP profile holds all the configuration needed to identify and connect a SIP account — except credentials. Passwords and authentication secrets are stored separately in the OS keychain (ADR-009, deferred).

Profiles are managed by `SipProfileManager` (`src/sip/SipProfileManager.h`). Each profile is an instance of `SipProfile` (`src/sip/SipProfile.h`).

---

## SipProfile Fields

| Field | Type | Required | Default | Notes |
|---|---|---|---|---|
| `profileId` | `QString` | yes (auto) | UUID v4 | Generated by `SipProfile::createNew()` |
| `displayName` | `QString` | yes | — | Human-readable label, shown in UI |
| `sipUsername` | `QString` | yes | — | SIP username (localpart of URI) |
| `sipDomain` | `QString` | yes | — | SIP domain |
| `sipUri` | `QString` | no | derived | `sip:<username>@<domain>` if empty |
| `registrar` | `QString` | yes | — | SIP registrar address |
| `proxy` | `QString` | no | — | Outbound proxy (optional) |
| `outboundProxy` | `QString` | no | — | Second outbound proxy hop (optional) |
| `transport` | `SipTransport` | no | UDP | `UDP`, `TCP`, or `TLS` |
| `authUsername` | `QString` | no | — | Auth username if different from `sipUsername` |
| `emergencyServiceUri` | `QString` | no | — | PSAP SIP URI (ETSI placeholder) |
| `enableRtt` | `bool` | no | false | Enable Real-Time Text |
| `enableLmpe` | `bool` | no | false | Enable LMPE encoding |
| `enableEtsiCompatibility` | `bool` | no | false | ETSI TS compliance mode |
| `createdAt` | `QDateTime` | auto | UTC now | Set on first `add()` |
| `updatedAt` | `QDateTime` | auto | UTC now | Updated on every `update()` |

**Passwords are not a field.** See [Credential Storage](#credential-storage) below.

### SIP URI Derivation

`effectiveSipUri()` returns:
1. `sipUri` if it is explicitly set, or
2. `sip:<sipUsername>@<sipDomain>` otherwise.

## Validation Rules

`SipProfileManager::validate()` enforces:

| Rule | Error message |
|---|---|
| `displayName` not empty | "Display name is required" |
| `sipUsername` not empty | "SIP username is required" |
| `sipDomain` not empty | "SIP domain is required" |
| `registrar` not empty | "Registrar address is required" |

Transport is always valid since it is represented as a `SipTransport` enum. Invalid transport strings loaded from a hand-edited INI fall back to UDP and emit a `Warn` log.

## Persistence

Profiles are stored in a dedicated INI file separate from general application preferences:

| Platform | Path |
|---|---|
| Windows | `%APPDATA%\SIPClient\SIPClientProfiles.ini` |
| Linux | `~/.config/SIPClient/SIPClientProfiles.ini` |

**Settings key layout:**

```ini
[profiles/<profileId>]
displayName=Alice
sipUsername=alice
sipDomain=example.com
sipUri=sip:alice@example.com
registrar=registrar.example.com
proxy=
outboundProxy=
transport=UDP
authUsername=
emergencyServiceUri=
enableRtt=false
enableLmpe=false
enableEtsiCompatibility=false
createdAt=2026-06-22T10:00:00Z
updatedAt=2026-06-22T10:00:00Z

[active]
profileId=<profileId>
```

**No password or secret fields are ever written.** The test `noPasswordFieldsStored` verifies this automatically.

---

## Credential Storage

SIP account passwords are **not** stored in `SipProfileManager` or any INI file. This is by design (ADR-009). A future `CredentialStore` will wrap:
- **Windows:** Windows Credential Manager
- **Linux:** libsecret / KWallet

Until that task is implemented, the SIP stack will be initialized without credentials (registration is not attempted yet).

## SipProfileManager API

```cpp
// Singleton (production use)
SipProfileManager &mgr = SipProfileManager::instance();

// CRUD
QString id = mgr.add(profile);        // returns profileId, empty on validation failure
bool ok    = mgr.update(profile);
bool ok    = mgr.remove(profileId);

// Queries
QList<SipProfile> all = mgr.profiles();
SipProfile p          = mgr.profile(profileId);
bool exists           = mgr.hasProfile(profileId);

// Active profile
mgr.setActiveProfileId(id);
QString id     = mgr.activeProfileId();
bool hasActive = mgr.hasActiveProfile();
SipProfile p   = mgr.activeProfile();

// Validation
ProfileValidationResult r = mgr.validate(profile);
if (!r.valid) { /* r.errors is a QStringList */ }

// Transport conversion
QString s       = SipProfileManager::transportToString(SipTransport::TLS); // "TLS"
bool ok = false;
SipTransport t  = SipProfileManager::transportFromString("TLS", &ok);      // ok=true
```

### Signals

| Signal | When emitted |
|---|---|
| `profileAdded(QString profileId)` | After successful `add()` |
| `profileUpdated(QString profileId)` | After successful `update()` |
| `profileRemoved(QString profileId)` | After successful `remove()` |
| `activeProfileChanged(QString profileId)` | When active profile changes (empty = cleared) |

## Logging

Profile actions are logged via `Logger` (category `Sip`):

| Action | Level | Message |
|---|---|---|
| `add()` — validation failure | Warn | "Profile validation failed: …" |
| `add()` — success | Info | "Profile added: \<name\> (\<id\>)" |
| `update()` — not found | Warn | "Update failed — profile not found: \<id\>" |
| `update()` — validation failure | Warn | "Profile update validation failed: …" |
| `update()` — success | Info | "Profile updated: \<name\> (\<id\>)" |
| `remove()` — not found | Warn | "Remove failed — profile not found: \<id\>" |
| `remove()` — success | Info | "Profile deleted: \<name\> (\<id\>)" |
| `setActiveProfileId()` | Info | "Active profile selected: \<id\>" |
| Load: stale active id | Warn | "Stored active profile id \<id\> not found; clearing" |
| Load: invalid transport | Warn | "Profile \<id\>: unrecognised transport value, defaulting to UDP" |

**Secrets are never logged.**

## Test Isolation

Tests use a separate org/app to avoid touching real user settings:

```cpp
static constexpr const char *kTestOrg = "IrymeTest";
static constexpr const char *kTestApp = "SIPClientTest_Profiles";

SipProfileManager mgr(kTestOrg, kTestApp);
```

The `init()` and `cleanup()` hooks purge the test settings before and after each test case.

## Known Limitations

- No profile editor dialog — the Add/Edit buttons in `SidebarPanel` log "not implemented".
- No SIP registration — `SipProfileManager` is persistence-only; PJSIP integration is deferred.
- No credential storage — deferred to the Secure Credential Storage task (ADR-009).
- `emergencyServiceUri` is persisted but not used — ETSI emergency integration is future work.
